\chapter{Introduction}

Although most embedded software developers recognize the importance of strong
typing, as a tool to write more reliable software, many get discouraged of
using Ada, the strongest-typed language there is, just because of its syntactic
verbosity, or perhaps simply because Ada does not look more like C.

What if we could have a new programming language for embedded software that looks
like C but has an Ada soul, that is, a language with all the Ada concepts but
in a C skin, C with a strong-typed armor, and where using pointers is more
the exception than the norm.

This document presents the \emph{stC} (\emph{``Strong-Typed C''} programming language)
for safety-critical embedded software development.

A proof-of-concept compiler for \emph{stC}, known as \verb'stcc', has been written
in SPARK Ada. SPARK Ada \cite{SparkAda} is a high integrity subset of the Ada programming
language. The code of \verb'stcc' is available in GitHub at \url{https://github.com/jgrivera67/stcc}.

\section{Language Overview}
\begin{itemize}
\item \emph{stC} is a fully strong-typed language. That is, There is no automatic integer promotion
 or any other implicit type conversions.
\item There are no built-in integer types in \emph{stC}. All integer types must be explicitly declared,
using language constructs to define range-based or modular-based integer types. The only built-in
types \verb'bool' and \verb'char'.
\item Types can be qualified with logical predicates to support ``liquid types''
      (\emph{logically qualified} types).
\item Arrays cannot implicitly be treated as pointers and they carry their length when
      passed-in as parameters to functions.
\item There are no header files and no preprocessor.
\item Declarations can be in any order. Symbols can be used before they are declared.
      In \emph{stC} there is no need for function prototypes or forward declarations.
\item A translation unit has an explicit name specified at the beginning of the source file with the
      \verb'unit' keyword.
\item A translation unit (module) can import public declarations from other translation units, using their module names.
\item A translation unit can have private declarations that are not visible to other translation units.
\item A translation unit can have child translation units. A child unit is
      named by using its parent unit's name followed by a dot as a prefix.
\item  A child unit inherits all the public and private declarations of its ancestor units.
       However, inherited private declarations cannot be used in the visible parts of the unit's public
       declarations.
\item The language is case-sensitive. All reserved words are lower case.
\item The language is block-structured. Blocks are delimited by curly braces.
\end{itemize}

\section{stcc}
\verb'stcc' does not generate machine code at the moment. It is only a ``transpiler'' which
translates a \emph{stC} source file into equivalent SPARK Ada 2022 source code.

\begin{itemize}
\item For each \emph{stC} file an Ada package specification file (\verb'.ads') and an Ada package
body file (\verb'.adb') are generated. To compile these files with the GNAT compiler, the \verb'-gnatX' flag
must be used, to enable the curated subset of GNAT language extensions, which are used in the generated
files \cite{gnatX}.

\item Line number form the original \emph{stC} source file are included as end-of-line comments
in the generated Ada code.
\end{itemize}

\chapter{Lexical Elements}

\section{Tokens}
The lexical structure of \emph{stC} consists of the following token types:
\begin{itemize}
\item Keywords (reserved words)
\item Identifiers
\item Literals (integer, floating-point, character, string, boolean)
\item Operators
\item Punctuation symbols
\item Comments
\end{itemize}

\section{Keywords}
The following identifiers are reserved as keywords and cannot be used as identifiers:

\begin{lstlisting}
as          assert      auto        bool        break
case        char        compile_if  const       continue
convention  default     do          else        enum
false       for         foreign     goto        if
import      in          inout       invariant   lambda
modular     module      out         packed      post
pre         private     range       renames     return
size        sizeof      static      struct      subtype
switch      true        type        union       void
volatile    while
\end{lstlisting}

Note: \verb'machine_width' is not a keyword but a built-in constant (see section on Built-in Constants).

\section{Identifiers}
An identifier consists of a letter followed by zero or more letters, digits, or underscores:
\begin{lstlisting}
identifier   = letter (letter | digit | '_')*
letter       = 'a'..'z' | 'A'..'Z'
digit        = '0'..'9'
\end{lstlisting}

Identifiers are case-sensitive. Examples: \verb'myVariable', \verb'Count_1', \verb'MAX_SIZE'

\section{Literals}

\subsection{Integer Literals}
\emph{stC} supports three integer literal formats:
\begin{itemize}
\item \textbf{Decimal}: \verb'0', \verb'42', \verb'1234', \verb'1_000_000'
\item \textbf{Hexadecimal}: \verb'0x0', \verb'0x2A', \verb'0x4D2', \verb'0xDEAD_BEEF', \verb'0x8000_0000'
\item \textbf{Binary}: \verb'0b0', \verb'0b101010', \verb'0b1111_1111', \verb'0b1010_0101'
\end{itemize}

Both underscores (\verb'_') and apostrophes (\verb''') can be used as digit separators to improve readability:
\begin{itemize}
\item \textbf{Underscore style}: \verb'1_000_000', \verb'0xDEAD_BEEF' (Python/Rust style)
\item \textbf{Apostrophe style}: \verb'1'000'000', \verb'0xDEAD'BEEF' (C++14+ style)
\end{itemize}

Separators are allowed between digits but not at the beginning or end of a number, and not immediately after the base prefix (\verb'0x' or \verb'0b'). A literal must use only one separator style - mixing \verb'_' and \verb''' in the same literal is an error.

\textbf{Examples:}
\begin{lstlisting}
// Decimal with underscores
type range 0 .. 1_000_000 million_t;
type range 0 .. 4_294_967_295 uint32_max_t;

// Decimal with apostrophes (C++14+ style)
type range 0 .. 1'000'000 million_cpp_t;
type range 0 .. 4'294'967'295 uint32_max_cpp_t;

// Hexadecimal with underscores
type modular 0x8000_0000 half_max_t;
type modular 0xFFFF_FFFF uint32_all_bits_t;
type modular 0xDEAD_BEEF hex_pattern_t;

// Hexadecimal with apostrophes
type modular 0x8000'0000 half_max_cpp_t;
type modular 0xFFFF'FFFF uint32_all_bits_cpp_t;

// Binary with underscores
type modular 0b1111_1111 byte_mask_t;
type modular 0b1010_0101_1100_0011 pattern_t;

// Binary with apostrophes
type modular 0b1111'1111 byte_mask_cpp_t;
type modular 0b1010'0101'1100'0011 pattern_cpp_t;

// Invalid - mixed separators
// type modular 0x8000_0'000 invalid_t;  // Error!
\end{lstlisting}

\subsection{Floating-Point Literals}
Floating-point literals have the form:
\begin{lstlisting}
3.14
2.71828
1.0e10
6.022e23
\end{lstlisting}

\subsection{Character Literals}
Character literals are enclosed in single quotes:
\begin{lstlisting}
'a'  'Z'  '0'  '\n'  '\t'  '\\'  '\''
\end{lstlisting}

Escape sequences:
\begin{itemize}
\item \verb'\n' -- newline
\item \verb'\t' -- tab
\item \verb'\r' -- carriage return
\item \verb'\\' -- backslash
\item \verb'\'' -- single quote
\item \verb'\"' -- double quote
\item \verb'\0' -- null character
\end{itemize}

\subsection{String Literals}
String literals are enclosed in double quotes:
\begin{lstlisting}
"Hello, World!"
"Line 1\nLine 2"
"Path: C:\\Users\\name"
\end{lstlisting}

\subsection{Boolean Literals}
The boolean type has two literals: \verb'true' and \verb'false'

\section{Operators}
\emph{stC} provides the following operators, listed by precedence (highest to lowest):

\begin{center}
\begin{tabular}{|l|l|c|}
\hline
\textbf{Precedence} & \textbf{Operators} & \textbf{Associativity} \\
\hline
16 & \verb'.' \verb'->' \verb'[]' \verb'()' (function call, cast) & Left \\
15 & \verb'**' (exponentiation) & Right \\
14 & \verb'*' (deref) \verb'&' (address-of) \verb'sizeof' \verb'!' \verb'~' \verb'-' (unary) \verb'+' (unary) & Right \\
13 & \verb'*' \verb'/' \verb'%' & Left \\
12 & \verb'+' \verb'-' & Left \\
11 & \verb'<<' \verb'>>' & Left \\
10 & \verb'<' \verb'>' \verb'<=' \verb'>=' \verb'..' & Left \\
9 & \verb'==' \verb'!=' \verb'in' & Left \\
8 & \verb'&' (bitwise and) & Left \\
7 & \verb'^' & Left \\
6 & \verb'|' & Left \\
5 & \verb'&&' & Left \\
4 & \verb'||' & Left \\
3 & \verb'?' \verb':' (ternary) & Right \\
2 & \verb'=' \verb'+=' \verb'-=' \verb'*=' \verb'/=' \verb'%=' \verb'&=' \verb'|=' \verb'^=' \verb'<<=' \verb'>>=' & Right \\
\hline
\end{tabular}
\end{center}

\section{Comments}
\emph{stC} supports single-line comments starting with \verb'//' and extending to the end of the line:
\begin{lstlisting}
// This is a comment
int x = 42; // Comment after code
\end{lstlisting}

\section{Built-in Constants}
\emph{stC} provides platform-specific built-in constants that can be configured via compiler command-line options.

\subsection{Platform Constants}
The following built-in constants are available:
\begin{itemize}
\item \verb'machine_width' -- The native word size in bits (e.g., 8, 16, 32, 64)
\end{itemize}

\subsection{Compiler Options}
The \verb'machine_width' constant can be set using the command-line option:

\begin{lstlisting}
stcc --machine-width=64 program.stc
\end{lstlisting}

\textbf{Default value:} 32 (suitable for most embedded platforms)

\textbf{Example usage:}
\begin{lstlisting}
module stdint {
  // Creates a modular type sized to the platform's native word
  type modular 1 << machine_width address_t;
}
\end{lstlisting}

\chapter{\emph{stC} Grammar}

%\begin{grammar}
\begin{lstlisting}[numbersep=0pt,resetmargins=true]
<translation-unit> ::=
   "module" <module-name> "{"
   ("import" <module-name> ("as" <module-identifier>)? ";")*
   <declaration>*
   ("private"
    ("import" <module-name> ";")*
    <declaration>+)? "}"

<module-name> ::= "<identifier>" ("." "<identifier>")*

<module-identifier> ::= "<identifier>"

<declaration> ::=
   <constant-declaration> |
   <type-declaration> |
   <variable-declaration> |
   <function-declaration> |
   <foreign-variable-declaration> |
   <foreign-function-declaration> |
   <compile-if-declaration>

<constant-declaration> ::=
   "const" <type-identifier> <constant-declarator> "=" <constant-expression> ";"

<constant-declarator> ::=
   ("*")? <constant-identifier>
             ("[" "]" ("[" <constant-integer-expression> "]")*)? ";"

<constant-identifier> ::= "<identifier>"

<type-declaration> ::=
   "type" <type-declarator> <type-identifier> (<type-attributes>)? ";"

<type-identifier> ::= "<identifier>"

<type-declarator> ::=
   "range" <constant-integer-expression> ".." <constant-integer-expression> |
   "modular" <constant-integer-expression> |
   ("struct" | "union") "{" (<struct-field-declaration> ";")+ "}" |
   "enum" "{" <enum-entry> ("," <enum-entry>)* "}"

<struct-field-declaration> ::=
   <type-identifier> <struct-field-declarator> ("=" <constant-expression>)?

<struct-field-declarator> ::=
   ("*")? <struct-field-identifier>
            ("[" <constant-integer-expression> "]")*

<struct-field-identifier> ::= "<identifier>"

<enum-entry> ::=
   <enum-entry-identifier> ("=" <constant-integer-expression>)?

<enum-entry-identifier> ::= "<identifier>"

<global-variable-declaration> ::=
   "<type-identifier>" <global-variable-declarator>
   ("=" <constant-expression>)? (<variable-attributes>)? ";"

<global-variable-declarator> ::=
   ("*")? <global-variable-identifier>
            ("[" <constant-integer-expression> "]")*

<global-variable-identifier> ::= "<identifier>"

<function-declaration> ::=
   ("void" | <type-identifier> ("*")?) <function-identifier>
       "(" (<param-declaration> ("," <param-declaration>)*)? ")"
       (<function-attributes>)?
       <statement-block>

<function-identifier> ::= "<identifier>"

<statement-block> ::=
      "{" (<local-variable-declaration> | <statement>)* "}"

<local-variable-declaration> ::=
   "<type-identifier>" <local-variable-declarator> ("=" <expression>)? ";"

<local-variable-declarator> ::=
   ("*")? <local-variable-identifier> ("[" <index-expression> "]")*

<local-variable-identifier> ::= "<identifier>"

<statement> ::=
    <assignment> |
    <void-function-call> |
    <if-statement> |
    <while-statement> |
    <for-statement> |
    <do-while-statement> |
    <switch-statement> |
    <statement-block> |
    <return-statement> |
    <compile-if-statement>

<assignment> ::= <variable-reference> "=" <expression>

<void-function-call> ::= <void-function-reference>  "(" (<function-call-argument> ("," <function-call-argument>)*)? ")"

<void-function-reference> ::=
  <void-function-identifier> |
  <void-function-pointer-expression>

<if-statement> ::= "if" "(" <boolean-expression> ")" <statement-block> ("else" <statement-block>)?

<while-statement> ::= "while" "(" <boolean-expression> ")" <statement-block>

<do-while-statement> ::= "do" <statement-block> "while" "(" <boolean-expression> ")" ";"

<for-statement> ::=
   "for" "(" (<local-variable-declaration> | <assignment>)? ";"
   <boolean-expression>? ";"
   <assignment>? ")" <statement-block>

<switch-statement> ::=
   "switch" "(" <expression> ")" "{"
   <switch-case>*
   (<default-case>)?
   "}"

<switch-case> ::= "case" <constant-expression> ":" <statement>*

<default-case> ::= "default" ":" <statement>*

<return-statement> ::= "return" (<expression>)? ";"

<compile-if-statement> ::=
   "compile_if" <constant-expression> "{"
      <statement>*
   "}" ("else" "{" <statement>* "}")?

<compile-if-declaration> ::=
   "compile_if" <constant-expression> "{"
      <declaration>*
   "}" ("else" "{" <declaration>* "}")?

<param-declaration> ::=
   (<parameter-mode>)? <type-identifier> <param-declarator>

<parameter-mode> ::= "in" | "out" | "inout"

<param-declarator> ::=
   ("*")? <param-identifier> ("[" "]" ("[" <constant-integer-expression> "]")*)?

<param-identifier> ::= "<identifier>"

<function-call-argument> ::= <expression>

<foreign-variable-declaration> ::=
   "foreign" "convention" "(" <string-literal> ")"
   <type-identifier> <global-variable-declarator> ";"

<foreign-function-declaration> ::=
   "foreign" "convention" "(" <string-literal> ")"
   ("void" | <type-identifier> ("*")?) <function-identifier>
   "(" (<param-declaration> ("," <param-declaration>)*)? ")" ";"

<expression> ::= <ternary-expression>

<ternary-expression> ::=
   <logical-or-expression> ("?" <expression> ":" <expression>)?

<logical-or-expression> ::=
   <logical-and-expression> ("||" <logical-and-expression>)*

<logical-and-expression> ::=
   <bitwise-or-expression> ("&&" <bitwise-or-expression>)*

<bitwise-or-expression> ::=
   <bitwise-xor-expression> ("|" <bitwise-xor-expression>)*

<bitwise-xor-expression> ::=
   <bitwise-and-expression> ("^" <bitwise-and-expression>)*

<bitwise-and-expression> ::=
   <equality-expression> ("&" <equality-expression>)*

<equality-expression> ::=
   <relational-expression> (("==" | "!=" | "in") <relational-expression>)*

<relational-expression> ::=
   <shift-expression> (("<" | ">" | "<=" | ">=" | "..") <shift-expression>)*

<shift-expression> ::=
   <additive-expression> (("<<" | ">>") <additive-expression>)*

<additive-expression> ::=
   <multiplicative-expression> (("+" | "-") <multiplicative-expression>)*

<multiplicative-expression> ::=
   <power-expression> (("*" | "/" | "%") <power-expression>)*

<power-expression> ::=
   <unary-expression> ("**" <unary-expression>)*

<unary-expression> ::=
   <postfix-expression> |
   <unary-operator> <unary-expression> |
   "sizeof" "(" (<type-identifier> | <expression>) ")"

<unary-operator> ::= "+" | "-" | "!" | "~" | "*" | "&"

<postfix-expression> ::=
   <primary-expression>
      (("[" <expression> "]") |
       ("(" (<function-call-argument> ("," <function-call-argument>)*)? ")") |
       ("." <struct-field-identifier>) |
       ("->" <struct-field-identifier>))*

<primary-expression> ::=
   <identifier> |
   <literal> |
   "(" <expression> ")" |
   <type-cast-expression> |
   <lambda-expression>

<type-cast-expression> ::= <type-identifier> "(" <expression> ")"

<lambda-expression> ::=
   "lambda" "(" (<param-declaration> ("," <param-declaration>)*)? ")"
   "=>" <expression>

<boolean-expression> ::= <expression>

<index-expression> ::= <expression>

<constant-expression> ::= <expression>

<constant-integer-expression> ::=
   "<binary-integer-literal>" |
   "<decimal-integer-literal>" |
   "<hexadecimal-integer-literal>" |
   <constant-identifier> |
   <integer-unary-op> <constant-integer-expression> |
   <constant-integer-expression> <integer-binary-op>
      <constant-integer-expression>

<integer-unary-op> ::= "+" | "-" | "~"

<integer-binary-op> ::=
   "+" | "-" | "*" | "/" | "%" | "**" | "<<" | ">>" |
   "&" | "|" | "^"

<literal> ::=
   "<binary-integer-literal>" |
   "<decimal-integer-literal>" |
   "<hexadecimal-integer-literal>" |
   "<floating-point-literal>" |
   "<character-literal>" |
   "<string-literal>" |
   "<boolean-literal>"

<boolean-literal> ::= "true" | "false"

<variable-reference> ::=
  <variable-identifier> ("." <struct-field-identifier> ("[" <index-expression> "]")*)* |
  <variable-identifier> ("[" <index-expression> "]")*

<variable-identifier> ::= "<identifier>"

<void-function-identifier> ::= "<identifier>"

<type-attributes> ::=
   ("@" <type-attribute-name>)+

<type-attribute-name> ::= "size" | "machine_width" | "packed" | "at" "(" <constant-expression> ")"

<variable-attributes> ::=
   ("@" <variable-attribute-name>)+

<variable-attribute-name> ::= "at" "(" <constant-expression> ")" | "volatile"

<function-attributes> ::=
   <contract-clause>+

<contract-clause> ::=
   <precondition> | <postcondition> | <invariant>

<precondition> ::= "pre" "(" <boolean-expression> ")"

<postcondition> ::= "post" "(" <boolean-expression> ")"

<invariant> ::= "invariant" "(" <boolean-expression> ")"

\end{lstlisting}

\chapter{Examples}

\section{Simple Program}
A minimal \emph{stC} program:
\begin{lstlisting}
module hello {

  import stdio as io;

  foreign convention("C")
  int printf(in char* format);

  int main() {
    printf("Hello, World!\n");
    return 0;
  }

}
\end{lstlisting}

\section{Type Declarations}

\subsection{Range Types}
\begin{lstlisting}
module types_example {

  // Integer types based on ranges
  type range 0 .. 255 byte_t;
  type range 0 .. 100 percentage_t;
  type range -273 .. 1000 temperature_t;

  percentage_t cpu_usage = 75;
  temperature_t room_temp = 22;

}
\end{lstlisting}

\section{Functions}

\subsection{Simple Function}

\end{lstlisting}

\subsection{Function with Contracts}
\begin{lstlisting}
type range 0 .. 2147483647 natural_t;

natural_t divide(in natural_t a, in natural_t b)
    pre(b != 0)
    post(result * b <= a && result * b + b > a)
{
  return a / b;
}
\end{lstlisting}

\subsection{Function with Parameter Modes}
\begin{lstlisting}
void swap(inout int_t a, inout int_t b) {
  int_t temp = a;
  a = b;
  b = temp;
}

// Usage
int_t x = 10;
int_t y = 20;
swap(x, y);  // x=20, y=10
\end{lstlisting}

\subsection{If Statement}

  } else {
    return x;
  }
}
\end{lstlisting}

\subsection{Switch Statement}
\begin{lstlisting}
type enum {
    monday, tuesday, wednesday,
    thursday, friday, saturday, sunday
} day_of_week_t;

day_of_week_t day = monday;

switch (day) {
  case monday:
  case tuesday:
  case wednesday:
  case thursday:
  case friday:
    // Weekday
    break;
  case saturday:
  case sunday:
    // Weekend
    break;
  default:
    // Invalid
    break;
}
\end{lstlisting}

\section{Expressions}

\subsection{Ternary Conditional}
\begin{lstlisting}
type range -2147483648 .. 2147483647 int_t;

int_t max(in int_t a, in int_t b) {
  return (a > b) ? a : b;
}
\end{lstlisting}

\section{Compilation Unit Example}
\begin{lstlisting}
module geometry {

  type range -1000 .. 1000 coordinate_t;

  type struct {
    coordinate_t x;
    coordinate_t y;
  } point_t;

  coordinate_t distance_squared(in point_t p1, in point_t p2) {
    coordinate_t dx = p2.x - p1.x;
    coordinate_t dy = p2.y - p1.y;
    return dx * dx + dy * dy;
  }

  private

  // Private helper function
  coordinate_t square(in coordinate_t x) {
    return x * x;
  }

}
\end{lstlisting}

\section{Child Modules}
\begin{lstlisting}
// File: geometry.circle.stc
module geometry.circle {

  // Inherits point_t and coordinate_t from parent module geometry

  type range 0 .. 1000 radius_t;

  type struct {
    point_t center;
    radius_t radius;
  } circle_t;

  bool point_in_circle(in point_t p, in circle_t c) {
    return distance_squared(p, c.center) <= square(c.radius);
  }

}
\end{lstlisting}

\section{Compile-Time Conditionals}
The \verb'compile_if' statement allows for conditional compilation based on constant expressions evaluated at compile time. This is useful for platform-specific code or conditional features.

\subsection{Platform-Specific Types}
\begin{lstlisting}
module platform_types {

  // Define types based on platform word size
  compile_if machine_width == 64 {
    type range 0 .. (1 << 63) - 1 unsigned_long_t;
    type range -(1 << 63) .. (1 << 63) - 1 signed_long_t;
  } else {
    type range 0 .. (1 << 31) - 1 unsigned_long_t;
    type range -(1 << 31) .. (1 << 31) - 1 signed_long_t;
  }

  // Use underscores for readability in large numbers
  compile_if machine_width >= 32 {
    type modular 0x1_0000_0000 uint32_t;  // 4 billion
  }

}
\end{lstlisting}

\subsection{Numeric Literal Separators}
Both underscores and apostrophes can be used as digit separators in numeric literals to improve readability:
\begin{lstlisting}
module numeric_separators {

  // Underscore separators (Python/Rust style)
  type range 0 .. 1_000_000 million_t;
  type modular 0x8000_0000 half_uint32_t;
  type modular 0b1111_1111 byte_mask_t;

  // Apostrophe separators (C++14+ style)
  type range 0 .. 1'000'000 million_cpp_t;
  type modular 0xDEAD'BEEF hex_value_t;

  // Note: A literal must use only one separator style
  // type modular 0x8000_0'000 invalid_t;  // Error: mixed separators

}
\end{lstlisting}
